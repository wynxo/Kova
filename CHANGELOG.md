# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

- Choose any connected provider's model from the message box. The picker groups every configured model by connection (Local before cloud) with search, favourites and the active model ticked, and keeps a connected provider visible even when it has no model yet instead of silently dropping it; **Add provider…** and **Manage providers…** sit at the end of the same list. **Settings → Models and providers** now lists every connection with its address and model count, can add more of a provider's models later without asking for its key again (`GET`/`POST /providers/{id}/models`, catalog cached for a minute), and can remove a connection. A model chosen on the start screen is remembered for that device, a model chosen in a chat is saved on the chat, and both survive a reload; a fresh install now says **No model** and points at Add provider instead of naming the empty `local` placeholder, and a turn never sends that placeholder as if it were a model.
- The theme editor gains **Simple** and **Advanced** modes (#176). Simple starts from a chosen theme and offers an accent colour (with hover, pressed and on-text derived), a neutral/warm/cool background tone, and a text-contrast slider, while **Corners**, **Density** and **Font** use the same shared appearance preferences as Settings and stay outside the theme file. Advanced shows every semantic colour group, now including **Code**, beside the existing background layer; a failed WCAG pair marks the colour rows it names as well as listing the pair, and both modes preview on the real app. The corner preference is new and syncs with the other appearance choices, so `kova prefs export` carries it too.
- The diff review in the side panel gains **Undo file** (#190): every remaining hunk of one file is reverted in a single write, later edits made elsewhere in that file stay, and the whole undo is refused when any hunk was edited since it was shown. A file the change set created is removed when nothing is left. The undo is recorded as a new change set, so Restore files brings it back, and a paired phone still needs `host:exec` outside Kova Files.
- Projects can pin files from their working folder (#196): up to 20 project-relative references, set in the project editor, with repeatable `--pin` and `--unpin` (plus `--clear-pins`) on `kova projects create|edit`. Pins are references for the user only; their names and contents are not sent to the model. Absolute paths, `~` and `..` are refused, a changed folder needs its list in the same request, saves need `host:exec` from a paired phone, and backups carry the references (not the files), dropping them when the project's folder is not present on the restoring machine.
- Projects can keep their own memory (#196), off until you turn on **Give this project its own memory** in the project editor (`--memory` in `kova projects create|edit`). A project chat still sees global recall and its shared instructions, but reads and writes only its own notes, so two projects never share a fact; project notes are stored in a hidden folder, have their own size budget, and are deleted with the project. Memory tools and the opt-in post-turn review keep their existing permission and provenance controls, and backups carry project memory with the project definitions.
- Backups now carry projects (#196): `projects.json` keeps each project's name, instructions, colour, icon, default model and folder, and a restored chat returns to its project. Merge restores projects before chats, skips one that is already here, imports a colliding id under a fresh one and moves only that archive's chats, while an archive from before projects existed still restores its chats ungrouped. Project folders below the home folder are written as `~/...` and a restore keeps one only when it exists as a directory, never creating a path or leaving new chats in a missing folder.
- `kova setup --yes` now requires an explicit `--url` and skips interactive prompts, while still validating the connection and model list (#343).
- Stop one parallel tool call on its own (#192): each call in the live tree that is waiting or running has a Stop button (and Delete on its row), `POST /chats/{id}/tasks/{task_id}/stop` ends just that call as "Stopped", the model is told the user stopped it, and the other calls and the turn carry on. Sub-agents and a quoted result summary still wait for real delegated tasks.
- Theme gallery, second slice (#177): search the cards, **Try** a theme for 30 seconds (a Keep/Revert bar over the real app, reverting by itself and saving nothing), see each theme's version and author, **Update** an installed theme to a newer bundled copy and **Remove** an installed theme file with a confirming click. `kova themes gallery [words]`, `kova themes update [id]` and `kova themes remove <id>` do the same from the terminal; `POST /themes/gallery/{id}/update` and `DELETE /themes/{id}` need `settings:write` for a paired phone. A remote community catalog is not part of this.
- Theme backgrounds, second slice (#206): a fine **noise** texture joins gradients and images (`{"kind": "noise", "opacity": 0.06}`, drawn in the theme's own `fg.default`, no file), and the theme editor gains a Background section (none, gradient, noise, image) that previews live and is checked like the colours. Contrast is now measured against the worst-case background area: every gradient stop, the brightest grain, or a white and a black pixel of an image after its dim, each mixed 12% into the panel surfaces, in the editor, `POST /themes` and `scripts/validate_theme.py`. The default image `dim` rises from 0.35 to 0.55, the least that keeps the stock dark palette readable over any image.
- `/compare [-m a,b] <message>` in the terminal chats (#96), full-screen and plain: it asks two to four models the same message (the active model first, then the others, unless `-m` names them), shows the spinner while they answer, prints each answer with its speed and token count, and opens a picker to keep one, which saves your message and that answer as a normal turn. Esc keeps none, Stop cancels every model, and a Local only refusal shows the server's reason. `KovaClient.stream_compare` and `keep_compare` use the same endpoints as the web.
- Keyboard shortcuts are fully remappable and shared (#200). Settings > General > Shortcut keys starts from Default, Vim-ish or Emacs-ish (`Alt` `J`/`K` or `Alt` `N`/`P` move through the conversation list, and `Alt` is ignored while typing), and recording one key turns the choice into Custom. Bindings live in the `shortcuts` UI preference, validated on the server (known action ids, canonical chords, bounded size) so every paired device and `kova prefs export` carry them; `localStorage` stays a first-paint cache and the keys saved there before this are migrated once. The shortcuts dialog gains a search by action name or key, and the palette, the New chat button, the sidebar toggle and Stop show the keys you actually use.
- Compare answers in a chat (#96): the + menu, the model picker and the command palette open a chooser for two to four configured models, which all answer the same message at once, side by side on a desktop and as swipeable cards on a phone, each with its speed and token count, one Stop and a Keep this one button. Answers are plain replies (no tools, no memory) and nothing is saved until you keep one, which stores your message and that answer as a normal turn with its model and usage. `POST /chats/{id}/compare` streams the answers tagged by model and `POST /chats/{id}/compare/keep` saves the chosen one; Local only refuses a cloud model before anything is sent, and Stop, Local only or closing the stream cancels every model.
- The web app's live event stream connects again: a merge had made `/events` return 500, so reminders and background updates never arrived (#283).
- Two high-contrast example themes join the palette — a pure black-and-white dark and a matching light (#284).
- The app mark is now a monochrome K that stays sharp at 16px and inverts with the theme (#285).
- A Motion setting (Full, Reduced, Off) in Settings > General controls animations across the web and desktop apps (#286).
- Tool calls now group into one row showing status, time and failures, opening while a turn runs and folding when it finishes (#287).
- A green-phosphor Terminal example theme joins the palette (#289).
- Message actions add copy-as-markdown, retry, edit-and-resend and reply details (model, tokens, speed, timing, cost) (#290).
- Retry and edit keep every earlier attempt instead of deleting it (#188): the newest turn gets a quiet `‹ 2 / 3 ›` stepper to flip between replies, `POST /chats/{id}/alternatives` switches one back by `turn_id` and index, and archived attempts never enter model context, search, usage or a fork. Older turns and stamped history stay stored but cannot be flipped once a newer message exists.

- The composer gains up/down message history, @-mention completion and attachment chips with name, size and a remove button (#296).

Both are shared UI preferences like text size and density, so paired devices and `kova prefs export` carry them, and Normal/Avatars On write no rule at all.
- Code blocks gain a Lines switch beside Wrap and Copy (#189): a quiet gutter of line numbers, remembered per browser like Wrap, aria-hidden and never copied, hidden while a block wraps and left off for fences still streaming or over 2,000 lines.
- Replies gain GitHub-flavored callouts (`> [!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, `[!CAUTION]`) that render as labelled asides with the status tokens, and collapsible `<details>`/`<summary>` blocks keep their native keyboard behaviour (#189). The sanitizer's allowlist now admits only those two extra tags and `open`.
- The desktop window remembers its place, size and whether it was maximized as you move and resize it rather than only on quit, restores all three where the display it was on still exists, and starts fresh instead of off-screen when it does not (#203).
- The desktop window gains an optional themed title bar (`[desktop] title_bar = "themed"`, native by default) that paints from the active theme while keeping each OS's own window controls, and the native menu and tray now include the command palette, focus-message-box and Quick ask actions (#203).

The cache name is declared again (and bumped), and a test keeps a name out of the URL list. The shell list itself was also incomplete — `tokens.css`, Settings, the palette and the message actions were missing — so an offline load now has every asset the page asks for, with a test that compares the two lists.

- Pin a conversation from its sidebar menu: pinned chats stay on top and the rest are grouped into Today, Yesterday, Previous 7 days and Older by local calendar day (#195). `pinned` is stored on the chat, existing databases gain the column without losing anything, and every client shows the same order. A paired phone can pin with its ordinary `chat` capability: a pin is cosmetic, so it neither needs a stopped turn nor counts as the phone writing in that chat.
- Paired phones get a per-device capability set (#229). A new phone may chat and see local models (`chat`, `models:read`); installing or deleting local models (`models:write`), changing providers and model servers (`providers:write`), MCP servers, plugins and skills (`extensions:write`), and approval rules, privacy, the memory folder persona, memory settings or start at login (`settings:write`), and commands, scheduled jobs, MCP tools and files outside Kova Files (`host:exec`) need a capability granted from the computer with `kova devices allow ID CAPABILITY`. Memory writes need `memory:write`. The limits also apply inside the agent: a phone's turns are offered only the tools it may use, a chat a phone wrote in keeps its limits for every later turn, a phone-queued message runs bound to its own row and is never read as local input by the terminal or web app, and a phone can approve, answer, steer or queue nothing beyond its own capabilities. Writing or restoring `KOVA.md`/`AGENTS.md` or git data needs `host:exec` (and the terminal's file index runs git with `core.fsmonitor` off), removing jobs needs `host:exec`, a phone-set chat title or setting limits that chat, the memory folder is never writable as a shared folder, recall never surfaces a phone-limited chat to a stronger turn, backups keep chat limits, and messages queued before the upgrade are treated as a phone's. Phones paired earlier get the defaults. The matrix is in docs/remote-access.md.
- Add the extensions catalog (#137): `kova catalog search|show|install` and an **Extensions** page (Installed · Plugins · Skills) browse a JSON index from `[catalog] url`, with a bundled fallback that works offline. Every install is pinned by version and SHA-256, shows its source and exactly what it adds, and runs nothing until confirmed. `kova skills list|show|rm` and the Extensions page show every skill with its origin (learned by Kova, catalog, yours, plugin) and let you read, edit and delete it (#107). First-party extensions: the `clipboard` (#91) and `morning-briefing` (#95) plugins and two skills; `file-watcher` (#108) is listed as coming soon.
- Add opt-in outbound secret protection: `privacy.secrets = "off" | "redact" | "block"` (default `off`) scans every OpenAI-compatible, Anthropic and Responses request at `ModelClient`, redacts known credential shapes on a deep copy or blocks before any request, reports safe counts in the CLI and web UI, and bypasses only parsed loopback hosts (#78).
- Keep extracted attachment text out of stored messages, search, exports, backups and generated titles; it stays turn-only model context, and `read_attachment` still rereads files by id on later turns. Messages keep a name-only attachment link, so attachment-only turns show the file name after a reload and forked chats keep that link.
- Reap abandoned chat uploads after 24 hours and cap unsent uploads, per-chat attachments and total attachment storage; attachments referenced by saved messages are always retained (#151).
- Fix chat forks copying attachment references without independent files; failed copies roll back the fork.

- Add web/desktop slash commands, a mobile command picker, conversation forking and compaction controls.
- Attach up to three local documents or images per chat turn, with bounded local extraction, file chips, rereading and explicit model vision support (#74).
- Vision is per model: select a vision model to attach images without a reload, turn it on or off in Model settings (persisted to config.toml), and `GET /capabilities?model=…` reports that model's contract with a 404 for an unknown name (#151).
- File shares from the installed web app become native composer attachments uploaded through the existing attachment API and gated by the selected model's vision setting; text and link shares are unchanged. Unredeemed share-draft chats are removed at startup because their in-memory tokens cannot survive a restart.

### Added

- Add an installable app shell, one-use phone share drafts, and opt-in device reminders while the app is alive; closed-app push is not supported.

- Session picker gains fork: `/fork` copies the current chat (or `/fork 2` any earlier one), and **Ctrl+S** in the `/resume` picker forks the highlighted chat; forks keep messages and compacted context and continue independently.
- Remappable keyboard shortcuts: bind every chat action under `[tui.keys]` in `config.toml`.
- Light terminal theme: set `theme = "light"` under `[tui]`; colours adapt to a light background before terminal colour-depth downscaling.
- Progressive onboarding tips in the chat: one short tip per start instead of a one-shot key list.
- Onboarding names your assistant and picks a tone (warm, concise, professional, playful); the identity is used in the system prompt, the chat UI, the web UI and the desktop window and tray.
- Providers declare their capabilities once — tool calling, reasoning stream, sign-in style, address and header fields — and the CLI, terminal chat and web app offer only what is declared; the server refuses a forced unsupported action.
- Start Kova at login with `kova autostart on|off|status`: a per-user systemd unit (or `.desktop` fallback), macOS LaunchAgent, or Windows HKCU Run entry, with no administrator rights and no stale duplicates.
- `kova-web` command opens Kova's web UI in your browser.
- Terminal shortcut `Ctrl+T` toggles full model reasoning, streamed live.
- Terminal shortcut `Ctrl+O` expands and collapses tool calls and their output.
- Live streaming of commands and their output, and of code, as the model writes them.
- Queue a message for after the running turn, or steer the running turn itself, in the terminal and web UI. Queued messages are persisted and survive reloads.
- Per-turn change review with diffs and local, Git-independent restore points (`/changes`, `/diff`, `/restore`).
- Layered `KOVA.md` / `AGENTS.md` guidance from the Kova home, project root and working folder, with a 16 KiB budget and clear precedence.
- Linux Landlock sandbox for `run_command`: safe commands run without a prompt but cannot write outside the working folder.
- `kova doctor` now checks the command sandbox, port ownership, Node/npm for `kova-app`, token permissions, free disk and config schema, prints a verdict with a next step, and supports `--json`; the README documents every line.
- `install.ps1`, `uninstall.ps1` and their `.bat` wrappers are exercised on Windows CI with a disposable home, and `scripts/smoke.sh` now runs as its own CI job on every push.

### Changed

- `/health` answers from a 15-second cached model status refreshed in the background (`?probe=1` forces a live check), and the web poll pauses while hidden and backs off to 2–5 minutes, so CLI commands and open windows no longer wait on a down model.
- Approvals and `ask_user` questions are announced to screen readers and move keyboard focus to their first decision button (the transcript itself stays `aria-live="off"`); the web UI announces how a turn ended and returns focus to the composer after an answer.
- `kova-app` now launches the desktop app (native window; `--browser` for your browser).
- `./update` (`update.bat`) refreshes an installed `kova` with `uv tool install --editable` directly instead of running the installed command, so a stale tool environment that cannot import a newly added dependency repairs itself, and the failure message gives a recovery command that does not need `kova` (#341).
- `docs/ARCHITECTURE.md` now documents all 72 endpoints with their auth, plus the SSE event vocabulary; `uv run pytest -k architecture` fails when the table and the code drift apart.
- Redesigned desktop and web UI, with a new app icon.
- Reminder notifications now work on macOS and Windows and fall back from `notify-send` to `gdbus` on Linux; `kova doctor` reports the notifier in use, and the desktop app allows the Notification permission.
