# Bot ideas - research notes

Date: 2026-11-22 · Working notes for the bots-and-group-chats build. Concrete
ideas Kova could add on top of the design spec. Products named here are only
examples; the same file is public and this note is not shown in the app.

## Templates / starter bots

- Bundled "starter bots" as data in `bots.py` (like the design's section 2.2): a
  researcher, coder, writer, and a "buddy" / generalist. Each ships with a name,
  one-line description, persona, defaults, and no files until the user adds it.
- "Make your own" template: after editing a bot, offer **Save as a template**. The
  template is the definition + persona + group defaults, minus the avatar and the
  bot's private notes. (Grok Bot's "share a recipe, not a clone" is the same idea.)
- Prompt-library angle: a small set of persona *styles* (Socratic tutor,
  blunt reviewer, friendly coach) a user can stamp onto any bot, like a theme
  preview.
- "Clone this bot" from the bot card: make a fresh copy (new id, same definition)
  so a good setup can be forked without touching the original.

## Mini scripts / routines a bot could run

- Recipe routines in a folder (like `routines/`): a name, a `when` (cron or a
  natural-language trigger), and a `do` block the bot executes. The design's
  section 4 already has scheduled jobs; routines are the user-facing "what it
  does every morning" layer on top.
- Examples worth shipping: "morning briefing" (summarise unread mail/notes +
  calendar), "nightly recap" (what I worked on today), "watch a repo for changes",
  "weekly digest" of the group chat.
- A routine can *post into* a group (like a scheduled job), or just write to its
  own memory and surface it when asked. A routine posting into a group never
  triggers hand-offs (design section 4).
- "If this, then that" style triggers (a note arrives, a deadline is near) rather
  than only schedules - closer to Zapier's automation menu than to cron alone.

## Fun group behaviours

- Presets beyond the spec's Ask one / Panel / Team / Debate: a "brainstorm" preset
  (everyone, no cross-talk, list mode), a "viva" / defense (one answers, others
  challenge), a "speed round" (short, one line each).
- A rotating moderator: the lead passes the turn to another member each round so
  no single bot dominates.
- "Table read" / replay: bots restate what they each heard before answering, to
  cut up the shared context.
- A "quiet one" button per member that mutes it for the chat without removing it.
- Reactions a bot can send (a thumbs-up / a "noted") instead of a full reply, so a
  group does not spam.
- A debate timer shown in the queue row: each member gets N short turns, then a
  poll on who was convinced.

## Bot sharing as files

- Share a bot as a single file (the design's section 4 already lists
  `kova bots export|import` for later): a `.kobot` or `.agentkit`-style bundle, or
  just a tar of the bot folder with the definition + persona + avatar, no private
  memory.
- Import preview: before installing a shared bot, show its definition, tools, and
  ceiling so the user sees what it would be allowed to do.
- Share a whole group as a preset file: name, bots, and the group settings, so a
  good team setup can be copied (design's open item: user-made group presets).
- A gallery / catalog of shared bots and presets, like the theme gallery, from a
  local index or a link.

## On the "you see every step" promise

- Every idea above keeps the design's core: visible, stoppable, attributed turns.
  Even fun behaviours stay bounded by the group's limits and never hide a tool
  call.
